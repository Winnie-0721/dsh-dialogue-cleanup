## 3. 缺陷闭环（原风险 → 复现 → 修复 → 回归测试）

### 3.1 运行态检查与磁盘删除之间的竞态

- **原风险**：`judgeRunning` 通过后到 `rm` 之间，会话可能开始运行 → 删掉正在用的会话，**不可逆**。
- **复现方式**：先调查公开 API，再构造「第一次检查 idle、删除过程中变 running」的确定性用例。
- **调查结论（实测）**：DSH **有**内核级写锁 `SessionWriteLease`（Windows 命名信号量
  `Local\dsh-session-lock-<sha256(realpath)>` / POSIX fd 锁，占用抛 `SessionAlreadyOwnedError`），
  但**不对插件暴露** —— 无 export 块、无 `ctx.*` 挂载，唯一外部表现是 resume 的
  `session/writer-held` 错误码。**故不能声称竞态已消除。**
- **修复方式**：`removeArtifacts` 接受 `beforeDelete` 回调，在**每个 `rm` 之前**再判一次运行态
  （每次取**新鲜**快照，不吃批量快照）；判为 running 或状态不可知 → 跳过该目录、
  记 `skippedDetails` 与 `degradations`（`step: "preDeleteRecheck"`），结果 `partial`。
- **回归测试**：`fault-injection.test.mjs` →
  `§4.1 竞态：删除前二次确认发现会话已 running → 拒绝删除且磁盘零改动`、
  `§4.1 反向断言：全程 idle → 正常删除且不得误报 preDeleteRecheck`。
- **残余**：窗口压到单条语句级但**不为零**；彻底解决需宿主公开写锁。

### 3.2 `sessions.list()` / 会话身份查询失败被静默

- **原风险**：抛错/非数组/服务缺失被同一个 `catch` 压成 `liveIdsKnown=false`，用户看到 `complete:true`。
- **复现方式**：让 `sessions.list()` 抛错 / 返回非数组，观察 `degradations` 是否为空。
- **修复方式**：三态区分 —— 服务缺失=能力缺失（不算失败）；抛错/非法类型=真失败（`step: "readLiveIds"`）；
  空数组=正常结果。`sessionQuery.listSessions()` 失败原本已 fail-closed（不碰对偶拼写），
  现在同样进 `degradations`（`step: "readPersistedIds"`）并说明「守卫已收紧」。
- **回归测试**：`§4.2 sessions.list() 抛错/返回非数组 → 必须进 degradations`、
  `§4.2 反向断言：服务缺失/正常空数组 → 不得误报 readLiveIds`、
  `§4.2 sessionQuery.listSessions() 抛错 → 守卫收紧 + 必须报 readPersistedIds`、
  `§4.2 ... 返回非数组 → 同样收紧且可观测`。

### 3.3 项目目录符号链接被跳过但未报告

- **原风险**：Windows `readdir` 对重解析点报 `isDirectory:false`，循环开头直接跳过，
  既不进 `skipped` 也不进 `failures` —— 「跳过了潜在数据」被报成完整成功。
- **复现方式**：用 `mklink /J` 造项目目录链接，断言结果里能否看到「跳过了链接」。
- **修复方式**：记入结构化 `skippedDetails`（`reason: "project-dir-is-link"`）并进 `degradations`；
  `skipped` 仍保留字符串数组以兼容既有契约。`isRealPathInside` 在每次 `rm` 前仍保留（正反断言钉住）。
- **回归测试**：`§4.3 项目目录是符号链接 → 安全跳过，且必须进 skippedDetails + degradations`；
  既有 `isRealPathInside：真实路径在 root 内 → true；经链接逃逸 → false`。

### 3.4 批量删除语义含糊、无法精确重试

- **原风险**：重复 id 报 `total:2/ok:2`（第二次其实是 no-op）；失败与降级混在一起；无重试清单。
- **复现方式**：提交 `["d1","d1","d1"]` 与「成功+运行中+不存在」混合批次，看统计与逐条语义。
- **修复方式**：`requested`/`duplicates`/`total` 分离；逐条 `outcome`
  （`deleted`/`noop`/`refused`/`blocked`/`failed`）+ `retryable`；`retry[]` 只含需重试条目；
  `allComplete` 整批全绿才 true。
- **回归测试**：`test/batch-semantics.test.mjs` 全部 5 条。

### 3.5 变异测试自身退化（CI 门禁的真实价值）

- **原风险**：我改动 `artifacts.js` 的返回结构后，变异 N3 的 `find` 串不再命中 →
  脚本打 `SKIP` 并**把它计入 survived**，但脚本仍退出 0。若 CI 只看退出码，
  这条断言就悄悄变成装饰品。
- **复现方式**：改代码后重跑变异，观察到 `SKIP N3` 与 `survived 1`。
- **修复方式**：把 N3 的 `find` 串收窄为只锚定 `rm` 的 `catch` 块（不再跨越到函数尾部）；
  同时 CI 明确要求 `survived === 0`（而非只看退出码）。
- **回归**：`killed 71 / survived 0`。

### 3.6 审计日志无轮转、字段过肥

- **原风险**：实测 38 行 33.8 KB ≈ **910 B/行**（整份 `runtime` + 标题 + 全部 `removedPaths`），
  无容量上限，长期无限增长。
- **修复方式**：字段最小化 + 每字段定长截断（240 字符）；按大小轮转
  （`auditMaxBytes` 默认 4 MiB、`auditRotateKeep` 默认 3）；rename 搬走整份不截断正在写的日志；
  轮转失败返回 `rotateError` 但不阻断写入、不让删除事务失败；路径规范化并校验必须在
  `<DSH_HOME>` 内，越界**拒绝写入并如实上报**。
- **实测效果**：单行 **910 B → 196 B（约 4.6×）**。
- **回归测试**：`test/audit.test.mjs` 全部 14 条（含并发 50 条、轮转不截断、路径越界、禁用）。

### 3.7 CI 的 TAP 断言写法错误（会导致每次假红）

- **原风险**：`npm test -- --test-reporter=tap` 把旗标追加在文件实参之后，
  node **静默忽略**（实测输出仍是 `ℹ tests N`，没有 `# tests N`），
  CI 的 `grep '^# tests'` 永远匹配不到 → 测试全绿但 CI 每次红。
- **复现方式**：本地实跑两种参数位置并比对输出。
- **修复方式**：改为 `node --test-reporter=tap --test "test/**/*.test.mjs"`（旗标在 `--test` 之前），
  并在注释里写明原因。本地模拟 CI 断言：`# tests 238`，≥200 → PASS。

#### 首次远端运行抓出的两个真问题（本地 Windows/Node 24 测不出来）

**① Node 20 的 `node --test` 不支持 glob**

```
Could not find '/home/runner/work/.../test/**/*.test.mjs'
```

glob 展开是 **Node 22+** 才有的能力，而 `engines.node` 声明 `>=20.0.0` ——
也就是说「声明的跑法」在最低支持版本上**根本跑不起来**。
`package.json`、`release.ps1`、`ci.yml` 三处都用了这个 glob，全部统一到
新增的 `scripts/run-tests.mjs`（由 Node 自己枚举 `test/*.test.mjs` 再传给
`node --test`），三个版本、两个平台行为一致。

**② `isInside` 测试硬编码 Windows 路径**

```
not ok 236 - isInside 挡住越界（含大小写与归一化）
```

POSIX 上 `path.resolve()` 把反斜杠当**普通文件名字符**，`C:\tmp\sessions`
变成一个没有分隔符的单段路径，`startsWith(root + sep)` 必然不成立。
**这不是 `isInside` 的 bug，是测试的平台假设错误。**
改为按 `process.platform` 选路径形状，两边测同一套语义。
